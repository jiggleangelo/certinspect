# Schema Studio · MIT · 1.0.0

Open index.html with sibling core.js, app.js and style.css. Paste/import v1 DDL, optionally v2, select PostgreSQL or SQLite and Inspect. No SQL executes. Relationship cards provide a responsive text DOM map: PK diamonds, column types, NOT NULL, UNIQUE groups, FK source → target, index inventory. Current schema/export is v2 if supplied; lint includes labeled v1 and v2 findings. JSON preserves the schema, lint and diff; Markdown exports the current schema. Both exports keep full data.

Supported syntax: CREATE [TEMP|TEMPORARY] TABLE [IF NOT EXISTS] [schema.]name (...); CREATE [UNIQUE] INDEX [IF NOT EXISTS] name ON [ONLY] [schema.]table [USING method] (...). Column and named/table PRIMARY KEY, UNIQUE and FOREIGN KEY / REFERENCES, composite key lists, explicit NOT NULL/NULL, type arguments/arrays/multiword types, defaults with literals/functions/parentheses/casts, CHECK parentheses, COLLATE and GENERATED ALWAYS AS (...) STORED/VIRTUAL. SQLite STRICT / WITHOUT ROWID suffixes are recognized. IF NOT EXISTS does not merge repeated definitions; duplicates are errors. Inline ASC/DESC PK and AUTOINCREMENT are recognized. Semicolons inside quoted strings, doubled quotes, SQL dollar strings, nested section comments and line comments stay inert. Identifiers accept SQL double quotes and SQLite brackets/backticks; PostgreSQL unquoted keys fold lowercase; SQLite keys fold lowercase including quoted spelling. Display names retain identifier spelling.

This is a structural subset, not a SQL engine, query planner, full grammar or semantic validator. Unsupported top-level statements, CREATE TABLE AS and unfamiliar clauses fail visibly; arbitrary user-defined/multiword type text is retained without catalog validation. CHECK/generated/default expressions are not evaluated. FK action/deferrability suffixes and some constraint suffixes are not analyzed; a note marks them. No ALTER parsing, expression parsing, RLS, inheritance, partitions, domains, enum definitions, collation semantics, SQLite ON CONFLICT or catalog/search_path resolution. Unqualified FK lookup uses an explicit same-schema fallback; actual database search_path is not known. Standalone index targets must match a supplied table name. Tables and identifier casing must use the selected dialect consistently. PK implies NOT NULL in the PostgreSQL model; SQLite explicit NOT NULL is recorded separately and a note points out INTEGER PRIMARY KEY / WITHOUT ROWID exceptions.

Lint: missing PK, absent FK target/table columns, arity, nonunique referenced keys, unindexed FKs, SQLite PK nullability and subset notes. FK index coverage requires ordered leading source columns of a primary/unique key or full simple btree/default index. Partial/expression and non-btree indexes are excluded conservatively. This is a portability/performance hint: database-specific behavior and indexes outside pasted DDL are unknown. Foreign referenced-key checks likewise use supplied PK/UNIQUE/full unique indexes; expression, collation and partial predicates cannot prove uniqueness.

Diff treats identifier equality literally per dialect; renames appear as drops/additions. Reports destructive table/column drops, added columns/tables, NOT NULL changes and PK/UNIQUE/FK definition changes. PostgreSQL narrowing recognizes integer widths, text/varchar/char length limits, numeric integer-digit and scale reductions, and double-to-real precision. Other type changes are flagged for manual review, never labeled bounded. SQLite declared length/width changes are TYPE_CHANGE review warnings because affinity/STRICT rules do not behave like PostgreSQL. Index-only changes remain visible in schema/index inventories but have no separate diff diagnostic. No data, defaults/backfills, compatibility, type coercion, index performance or actual migration execution is inspected. A zero-finding result applies only to the supported model.

Bounds: 500,000 input characters, 80,000 lexical tokens, 150 tables and 64 parenthesis levels. Oversized/malformed input fails atomically, clears old results/exports and never generates approximate output. File bytes limited to 2 MB, then parser character bounds apply. Markdown escapes HTML/pipe/newline content; JSON retains literal values. Text enters the UI through DOM text nodes only; no dynamic HTML or URL interpretation. No persistence; Clear removes current state. No live data test data.


## Run, test and fork

Open `index.html` beside the supplied JavaScript and CSS files, or use any static server. The delivery includes paired suites and their shared test support. Use the delivery's `verify.sh` to run the complete suites in a disposable workspace with WebCrypto enabled; some retained suites require that workspace. The tool entrypoint is `tests/core.test.mjs` (`node:test`). Fork the MIT source and retain its license.
