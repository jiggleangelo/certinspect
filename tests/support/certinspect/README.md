# Certificate Lens · MIT · 1.0.0

Open index.html with sibling scripts and stylesheet. Paste one or more CERTIFICATE PEM sections, or import PEM/DER. Choose reference date/time in the control labeled UTC (the displayed local-style fields are explicitly interpreted as UTC), then Inspect. Use current UTC refreshes the reference once; the countdown is a snapshot and does not tick silently. Export JSON includes decoded fields, exact SHA-256 fingerprints, validity status and chain findings. Changing input/reference immediately invalidates old results. PEM order is preserved. A DER import contains one certificate; editing the placeholder replaces its bytes with the textarea input.

Decodes X.509 Certificate / TBSCertificate v1/v2/v3, positive serial, issuer/subject RDN attributes, UTCTime and GeneralizedTime (seconds, Z only), signature/public-key algorithm OIDs, SAN DNS and IPv4/IPv6, Key Usage bits, EKU OIDs/labels, Basic Constraints CA/pathLen and unknown-extension inventory. SHA-256 fingerprints cover the original complete DER bytes; native SubtleCrypto is used when available, with an original pure-JS fallback. Private-key PEM, mixed text, malformed/noncanonical padding, trailing DER data, indefinite/nonminimal lengths/integers, bad strings/times/structures, duplicate extensions and invalid recognized extensions fail atomically. Signature field and inner/outer algorithm equality are structural checks only.

Validity interval is inclusive at both boundaries. Status is not-yet-valid / valid-at-reference / expired. Countdown uses whole seconds truncated toward zero and days rounded to three decimals; negative values mean expired. No machine clock is assumed after the reference is selected. GeneralizedTime is accepted for any four-digit year as an inspection convenience; this reader does not enforce every RFC profile restriction, serial size recommendation, algorithm parameter rule, KU policy or certificate policy. It is not a complete universal ASN.1/BER/CER library. DER SET ordering, primitive/constructed forms and recognized value encoding are checked; unknown extension syntax is parsed structurally, not semantically. Directory strings support UTF-8, PrintableString, IA5, NumericString, BMP and UniversalString; legacy Teletex bytes are displayed byte-preserving, not a full T.61 repertoire. DNS values are displayed as encoded ASCII, not IDNA/hostname validated. Other GeneralName types are inventoried in notes.

Chain convention: leaf → immediate issuer → root. Adjacent issuer/subject RDN names use approximate Unicode-normalized, whitespace-collapsed, lowercase attribute equality, with RDN ordering retained and attributes sorted within each RDN. This is only a hint, not full RFC 5280 name matching or proof of issuer identity. Duplicate fingerprints, self-issued certificates before the end, name mismatches, issuer CA flag, issuer keyCertSign when KU is present, pathLen vs supplied subordinate non-self-issued CAs, and a non-self-issued final certificate are linted. Missing final issuer is reported as incomplete, not definitively invalid. Missing CA=true is a conservative warning for historical v1 anchors. A single self-issued certificate can have zero order findings. Self-issued means a name match; only native test data-author/test verification proves our retained demo certificates self-signed.

No cryptographic signature validation, trust store, path construction, root trust, hostname validation, revocation/OCSP/CRL fetch, policies, name constraints, key strength judgment or active certificate retrieval. Zero findings and current validity never mean recognized or cryptographic. Signature bytes may be invalid yet structurally decodable. Unknown critical extensions produce a note. Original DER name encodings remain available as public hex evidence in JSON.

Bounds: PEM text 1,500,000 characters; decoded DER chain total 1,048,576 bytes; 16 PEM certificates; 32 ASN.1 nesting levels; 20,000 nodes per DER value; OID payload 128 bytes. File limit 1.5 MB. Errors clear stale outputs, and pending async hash/read operations cannot restore them after an edit. No input persistence or requests. Public certificates only; never paste private keys.

the demo CA certificate in DER and PEM formats and demo-other.{der,pem} are original fictional Ed25519 self-signed public certificates, generated locally with in-memory keys that were discarded. They use .invalid names and documentation-only IPs, constant 2025–2035 dates, synthetic serials, SAN/KU/EKU/BC. the sample certificate generator embeds the exact same demo-ca PEM to load without a fetch. Native Node X509Certificate verifies each retained test data's self-signature and fingerprint during tests.


## Run, test and fork

Open `index.html` beside the supplied JavaScript and CSS files, or use any static server. The delivery includes paired suites and their shared test support. Use the delivery's `verify.sh` to run the complete suites in a disposable workspace with WebCrypto enabled; some retained suites require that workspace. The tool entrypoint is `tests/core.test.mjs` (`node:test`). Fork the MIT source and retain its license.
